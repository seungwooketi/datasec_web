데이터 주권 - 데이터 댐에서 데이터 스페이스로

전체 글 읽기 ↗그림, 비교표, 참고 문헌을 포함한 원문

이 글은 금승우 센터장의 개인 블로그에 올린 문서를 발췌한 것입니다. 원문은 seungwoo.datasec.work/blog/ko/industrial-data-sovereignty에서 보실 수 있습니다.

요즘 산업 AI 이야기가 많은데요, 결국 성패는 공장과 공급망에 흩어진 공정, 설비, 품질 데이터를 쓸 수 있느냐에 달린 경우가 많습니다. 2020년 한국판 뉴딜의 데이터 댐은 양질의 데이터를 한곳에 모아 개방하는 구상이었지만, 최근 데이터 주권의 흐름은 반대 방향으로 가고 있는 것 같아요. 데이터는 소유자에게 두고 계약된 범위에서만 쓰거나, 공통 모델과 학습 도구를 데이터 쪽으로 보내 학습시킨 뒤 파라미터만 돌려받는 식이죠.

모으는 방식의 한계

AI 학습용 데이터 구축 사업은 2017년부터 2024년까지 1조 6,328억원을 들여 908종의 데이터를 만들었는데요, 품질 목표 미달과 중복 구축이 감사에서 지적되기도 했습니다. 무엇보다 산업 AI에 정말 필요한 공정 조건, 설비 이력, 불량 데이터는 기업의 영업비밀이라 한곳에 모으기가 어렵구요.

데이터 주권을 구현하는 세 가지 방식

그럼 모으지 않고 어떻게 쓸 수 있을까요? 데이터 주권을 구현하는 방식은 크게 세 가지로 나눠 볼 수 있을 것 같습니다.

  • 중앙 집적형: 원본 데이터를 중앙 저장소로 모음 (데이터 댐)
  • 데이터 스페이스형: 데이터는 소유자 시스템에 두고 계약과 사용 정책 범위에서만 전송함 (GAIA-X, Catena-X)
  • 분산 학습형: 모델이 데이터 쪽으로 가서 학습하고 가중치만 돌아옴 (Project Tapestry)

GAIA-X와 산업 데이터 스페이스

2019년 독일에서 시작된 GAIA-X는 유럽형 클라우드 구상에서 출발했는데요, 지금은 참여자의 신원과 규칙 준수를 검증하는 신뢰 프레임워크로 자리 잡았습니다. 실제 데이터 교환은 Dataspace Protocol과 EDC 커넥터가 맡고, 계약 없이는 데이터가 오가지 않는 구조입니다. 2025년 11월에는 Gaia-X Hub Korea도 문을 열었구요.

이 원칙을 자동차 산업에 옮긴 Catena-X에서는 2026년 9월 기준 1,069개 기업이 데이터를 교환하고 있고, 품질 문제를 평균 4개월 먼저 찾아낸 사례도 보고되었습니다. 제조 전반으로는 Plattform Industrie 4.0이 주도하는 Manufacturing-X가 10개 과제로 넓어졌고, 국내에서도 산업데이터 스페이스 표준모델 사업(2026~2029)이 추진되고 있습니다.

IPCEI와 Project Tapestry

유럽은 IPCEI로 인프라와 AI 투자를 함께 묶고 있는데요. 2023년 승인된 IPCEI-CIS는 클라우드-엣지 연속체를, 19개국이 설계를 마친 IPCEI-AI는 산업 특화 파운데이션 모델을 맡으며, 두 사업 모두 데이터 스페이스와 Manufacturing-X를 관련 사업으로 명시하고 있습니다. 인프라, 데이터, 모델을 따로 보지 않고 한 묶음으로 보는 셈이죠.

AI Alliance의 Project Tapestry는 한 걸음 더 나아가 데이터를 아예 옮기지 않습니다. 각 참여자가 자기 데이터로 공통 기반 모델을 이어서 학습하고 가중치만 공유하는 '컨소시엄 학습' 방식인데요, 2026년 9월 두 건의 7B 규모 실증을 마쳤습니다.

산업 AI에 주는 시사점

그렇다면 가중치만 오가면 안전할까요? 꼭 그렇지는 않은 것 같아요. 산업 AI 관점에서 챙겨 볼 점은 다음 정도로 정리해 볼 수 있습니다.

  • 가중치 보호: 가중치만 공유해도 정보 유출과 오염 공격이 가능해 보안 집계, 차등 프라이버시, 병합 전 검증이 필요함
  • 실행 환경 증명: 참여 노드가 약속한 코드와 데이터로 학습했는지 확인하는 원격 증명이 필요함
  • 이력 연결: 데이터 사용 기록과 모델 단위 AI-BOM을 함께 추적할 필요가 있음
  • 클린룸과 분산 학습의 병행: 반출할 수 있는 데이터는 클린룸에서, 반출할 수 없는 공정 데이터는 분산 학습으로 다루는 구성을 고려해 볼 수 있음

데이터 댐이 데이터를 한곳에 모으는 구조였다면, 데이터 주권은 데이터를 제자리에 둔 채 그 가치가 흐르게 하는 구조라고 볼 수 있을 듯 합니다.

센터의 관련 연구는 과제 페이지에 정리되어 있습니다.
