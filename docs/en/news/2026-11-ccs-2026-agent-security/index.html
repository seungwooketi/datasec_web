ACM CCS 2026 - growing interest in AI and agentic AI security

Last week I was at ACM CCS 2026, the ACM SIGSAC conference, held this year in The Hague. One thing was clear: the security of agentic AI has become a topic in its own right. The idea of agentic AI is still young, but a run of hacks and security incidents involving agents has drawn attention to it quickly, and several papers this year dealt specifically with how agents call tools.

Here is how this year's main-conference papers compare with last year's.

I could not sit in on every session, and there were far too many papers to read every abstract. So I collected the titles and abstracts of the main-conference papers from OpenAlex and applied the same keyword rules to both years, then checked the agent candidates by hand. Posters, demos and workshops are left out. These are my own counts; a different rule would move the numbers a little.

By abstract keywords, agent-related papers went from two in 2025 to about twenty this year. The 16 in the table are the ones I checked by hand: papers on the security of agents themselves went from one to thirteen, and papers that use agents to attack or analyse systems went from none to three. Growth is expected for a concept this new. Still, agent security incidents have been in the news for less than a year, and the 16 checked papers alone already make up 3.3% of the main program, up from 0.3% last year. Research is widening fast from the security of LLMs and other ML models to the security of the agents built on them.

Three papers worth reading deal with agent tool calls and the Model Context Protocol (MCP), which is fast becoming the standard interface between agents and external tools:

  • ContractGuard: Auditing Semantic Contracts of MCP Tools for Security Violations checks whether what an MCP tool says it does matches what its code does, combining static analysis with LLM reasoning. Run on 3,586 tools from 1,000 real MCP servers, it found 116 security issues.
  • Governing AI Agent with Capability and Delegation Chain presents CapAgent, which keeps least privilege intact when agents hand authority to one another over several hops, using cryptographic credentials scoped to specific APIs and parameters. It integrates with MCP.
  • MetaMancer: Practical Tool Selection Attacks against LLM Agents manipulates tool metadata so that an agent picks a malicious tool. Without defenses the attack succeeds 92.7% and 93.8% of the time on two benchmarks. The paper also proposes a defense, CVR, that rebuilds tool metadata from the required parameters.

At our center we are working on safe tool integration for AI agents in operation: how to manage the information assets an agent can be given as tools (including under Korea's National Network Security Framework, N2SF), how to check that an MCP tool is safe, and how to detect tampering and forgery attacks. If this overlaps with your work, we would be glad to hear from you.

My field notes from the conference are in Notes from ACM CCS 2026.
