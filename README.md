# datasec-web — 인공지능데이터보안연구센터 홈페이지

`www.datasec.work` · GitHub Pages · 정적 · 한국어/영어 두 판.

```bash
python3 build.py          # docs/ 를 다시 그린다. 의존성 0
python3 -m http.server 8765 --directory docs
```

---

## 1. ⭐ 이 사이트는 KB 에 묻지 않는다

```
01. 센터 현황/*.xlsx        정본. 사람이 회사 시스템에서 내려받아 갱신한다
   └─ tools/pull_from_sot.py    사내에서만 돈다 (openpyxl + keti-kb 어댑터)
        └─ data/*.json          커밋된다. ⭐ 사이트가 읽는 것은 이것뿐이다
             └─ PR              리뷰가 곧 「무엇을 공개할지」의 결정이다
                  └─ docs/      build.py 산출물. Pages 가 그대로 서빙한다
```

런타임에 질의가 없다. 그래서 **DB 가 죽어도 사이트는 살아 있고**, 반대로 **KB 가 실수해도
그 실수는 PR 을 통과해야 공개된다.** 자동 게시로 만들면 사람이 고친 값을 다음 회차가 되돌린다.

## 2. ⛔ 배포 전에 반드시

```bash
python3 build.py --strict     # 하나라도 걸리면 종료코드 1
```

`--strict` 가 막는 것 셋 — **문서가 아니라 코드가 강제한다:**

| 차단 사유 | 왜 |
|---|---|
| `name_en_confirmed: false` 인 구성원 | 실존 인물의 이름이다. 로마자 표기는 **본인이 논문에 쓰는 철자**가 정답이고 추측이 아니다 |
| `sample: true` 인 뉴스 | 디자인 확인용으로 지어낸 글이다. 대외 공개물에 나가면 허위 사실이다 |
| 없는 과제를 가리키는 구성원 | 링크가 404 로 나간다 |

⚠️ 지금은 통과한다. ⛔ 그러나 **영문 이름 10명은 확인이 아니라 채택**이다 —
`박성주 → Sungjoo Park` 하나만 본인 확인을 거쳤고 나머지는 표준 로마자 표기를 그대로 썼다.
본인이 논문에 쓰는 철자와 다를 수 있으니, 알게 되면 `data/members.json` 에서 고친다.

## 3. 무엇을 싣고 무엇을 안 싣는가

**싣는다** — 과제명(국·영문) · 담당부처 · 수행기간(년-월) · 참여형태(주관/참여·공동/기업수탁) ·
책임자 · 구성원 이름·직급·수행 과제 · 집계 4종.

**안 싣는다** — 계정번호 · 과제번호 · 실행예산 · 월별 참여율(M/M) · 사번 · 개인 연락처 ·
제안/탈락 과제명 · 공동연구기관 목록.

마지막 둘의 이유가 특히 중요하다. **제안·탈락 과제명은 경쟁 정보**고,
**공동연구기관 목록은 한 칸에 여러 기관이 뭉쳐 있고 옛 기관명·자리표시자가 섞여 있어**
지금 상태로 내보내면 틀린 기관을 협력기관으로 게재하게 된다.

⛔ **부서 외 과제**(다른 센터가 이끄는 과제)는 **건수만** 싣는다. 남의 과제명을 우리 쪽에
올리지 않는다.

### 특정 과제를 빼야 할 때

`data/projects.json` 의 그 과제에 `"publish": false` 와 사유(`"withheld"`)를 넣는다.
⭐ **지우지 않는다.** 지우면 `tools/pull_from_sot.py` 가 정본과 대조할 때마다 "새 과제"로
다시 올려 결정이 사라진다.

빌드는 목록·상세 쪽·집계·구성원의 과제 목록에서 전부 뺀 뒤, **산출된 HTML 을 다시 훑어
과제명·slug 가 새어 나갔는지 확인하고 발견하면 차단한다** — 거르기를 믿지 않는다.
소식 글이 그 과제를 링크해 두었다면 그때 걸린다.

⚠️ 뺀 과제가 있으면 집계 숫자는 **공개 대상 기준**이 된다. 목록이 전부라고 말하는 문구를
쓰지 않는다.

지금은 **18건 전부 싣는다.**

## 4. 손대는 자리

| 무엇을 바꾸려면 | 어디를 |
|---|---|
| 소개문 · 협력 안내 · 연락처 | `content/site.json` |
| 소식 한 편 쓰기 | `content/news/<slug>.ko.md` + `.en.md` |
| 과제 소개 2~3문단 | `content/projects/<slug>.ko.md` + `.en.md` (없으면 「준비 중」으로 나간다) |
| 과제·구성원 값 | ⛔ 손으로 고치지 않는다 → `tools/pull_from_sot.py` |
| 색·글꼴·간격 | `assets/industry.css` — ⚠️ **디자인 시스템이다.** 값을 여기서 새로 정하지 않는다 |
| 이 사이트만의 배치 | `assets/site.css` |

소식은 **두 언어 다 있어야** 양쪽에 뜬다. 한쪽만 있으면 빌드가 경고하고 그 언어에서는 안 보인다.

## 5. 디자인

`design_handoff_aidsrc_site` 의 **Industry** 시스템을 따른다 — 강철색(`#5980a6`) 단일 강조,
`#f2f2f3` 바탕, Barlow Condensed 표제 / Barlow 본문 / 한글 IBM Plex Sans KR,
모서리를 굴리지 않고 카드에 면을 채우지 않는다. 액자는 `.blueprint` + 네 귀의 `+` 등록마크이고
**등록마크를 빼면 시스템 밖이다.**

핸드오프에서 **의도적으로 달리한 것 셋:**

1. **초상 격자를 쓰지 않는다.** 사진이 없다. 빗금 자리표시자를 대외 공개물에 내보내는 대신
   이름·직급·수행 과제를 읽히는 목록으로 뒀다. 사진이 들어오면 6단 격자로 되돌린다.
2. **Settings 쪽을 없앴다.** 언어 전환은 머리말에 있고, 접근성 토글과 뉴스레터는
   **받아 줄 곳이 없다.** 핸드오프도 *"구현하든가 빼라"* 고 적었다.
3. **그룹(Data/Privacy/Security/Governance) 축을 쓰지 않는다.** 그런 구분이 실제로 없다.
   대신 실재하는 축 — 참여형태·26년 신규 — 으로 걸러낸다.

한글 표제는 크기를 따로 준다(`site.css`). 88px 는 라틴 대문자 기준이라 한글에서 과하다.
`word-break: keep-all` 은 **빼면 안 된다** — 없으면 단어 중간에서 줄이 바뀐다.

## 6. Pages 에 올리기

⭐ **순서가 중요하다.** 도메인 검증을 리포에 붙이기 **전에** 해야 탈취를 막는다.

1. DNS 에서 `datasec.work` 의 기존 A/AAAA/CNAME(파킹·타 호스팅) 레코드를 **먼저 지운다** —
   남아 있으면 인증서 발급이 막힌다
2. GitHub 계정/조직 Settings → Pages → **Verify domain** → 토큰을 받아
   `_github-pages-challenge-<OWNER>.datasec.work` 에 **TXT** 등록 (반영 최대 24시간)
3. DNS 에 `www` → `<OWNER>.github.io.` **CNAME** — ⚠️ 리포 이름은 붙이지 않는다
4. apex 도 받으려면 `datasec.work` 에 **A 4건**
   (`185.199.108.153` · `.109.153` · `.110.153` · `.111.153`) + **AAAA 4건**
   (`2606:50c0:8000::153` ~ `8003::153`). 양쪽이 맞으면 GitHub 가 apex↔www 리디렉트를 자동 생성한다
5. 리포 Settings → Pages → Source **Deploy from a branch** · Branch `main` · Folder **`/docs`**
6. Custom domain 에 `www.datasec.work` → Save (GitHub 가 `docs/CNAME` 을 커밋한다.
   ⚠️ 그 커밋을 pull 하지 않으면 다음 `build.py` 가 덮어쓴다 — 내용은 같으니 무해하다)
7. 체크마크가 뜰 때까지 기다렸다가(최대 1시간) **Enforce HTTPS** 를 켠다

⚠️ **GitHub Free 는 public 리포만** Pages 를 쓸 수 있다. Pro/Team 이상이면 private 리포도
되지만 **발행된 사이트는 어차피 인터넷에 공개된다** — 사이트 자체를 비공개로 하려면
Enterprise Cloud 가 필요하다.

⛔ **리포를 지우거나 Pages 를 끄거나 요금제를 낮추기 전에 DNS 레코드를 먼저 지운다.**
남겨 두면 남이 그 주소에 자기 사이트를 올린다. 와일드카드(`*.datasec.work`)도 쓰지 않는다.

## 8. ⛔ 정본을 읽을 때 밟는 지뢰

`pull_from_sot.py` 가 이미 피하고 있지만, **다른 스크립트를 새로 쓴다면 같은 것을 밟는다.**

| 지뢰 | 무슨 일이 나나 |
|---|---|
| 모든 입력 시트에 `연번 = 예시` 인 행이 있다 | **실재 부서원 실명 + 지어낸 과제명 + 진짜 같은 억 단위 금액**이 들어 있다. 내용으로는 진짜와 구별되지 않는다 |
| 과제명에 `(R)`·`(C)`·`(N)` 접두와 이중 공백 | 이름으로 조인하면 **18건 전부 실패**하고, 도구는 "새 과제 18건"이라고 조용히 거짓말한다 |
| `과제기간` 옆에 `계정기간` 이 나란히 있다 | **18행 중 17행이 서로 다르다.** 계정기간은 회계연도 잘림이다 — 이걸 「수행기간」으로 실으면 17건의 종료년월이 전부 틀린다 |
| `계정기간_2026` 은 "수행 중"이 아니라 "2026년과 겹치는" 과제다 | 이미 끝난 과제가 섞여 있다(해양 디지털 항로표지, 2026-06 종료). 그래서 `build.py` 가 종료일로 상태를 **다시 판정한다** |
| `책임자` 오른쪽에 **머리글 없는 열**이 있다 | KETI 사번이다. 머리글 이름으로 거르는 필터에 안 걸린다 |
| `비고` 열이 6개 시트에 있다 | 이름은 무해한데 내용은 평가 일정·장소·계정번호·예산 금액을 담는다. **내용 검사 말고 열 자체를 뺀다** |
| 인원 수가 파일마다 다르다 | `명단` 12명 · `코드목록` 13명. 이 사이트는 **`명단` 을 따른다** |

⭐ 원칙: **화이트리스트로만 내보낸다.** 민감 열을 지우는 블랙리스트는 위의 함정을 전부 통과시킨다.
⛔ 그리고 **엑셀 파일 자체를 사이트에 올리지 않는다** — 시트 탭 이름만으로 부서원 실명 12개가 나간다.
